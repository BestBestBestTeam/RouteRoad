# Граница API фронтенда

`workdayApi.ts` выбирает реализацию; интерфейс `WorkdayApi` и модель `VisitDetails`
находятся в `src/types/workdayApi.ts`. Сейчас источник — асинхронный
`mock/demoWorkdayApi.ts` в памяти, без HTTP. Компоненты и stores не импортируют
фикстуры напрямую; API не импортирует React или stores.

## Текущий источник

- `loadRequests()` загружает новые неназначенные заявки, представителей и офис.
- `buildRoutes()` отдельно применяет предопределённый план и прямые линии.
- Методы списков обрабатывают типизированные query, поиск и страницы по 10.
- `getVisitDetails(id)` отдельно получает заявку, имя назначенного представителя,
  связанные алерты и историю. Карточка не ищет заявку в глобальном снимке.
- Мутации меняют демосостояние и возвращают копию полного snapshot.
- Сброс инвалидирует ожидающие операции; ошибки не превращаются в пустой успех.

Состояние дня не переживает перезагрузку. `MutationContext` содержит демоавтора,
но не даёт серверных полномочий. Временные действия отказа/назначения в демо
не являются окончательной реализацией интегрированного сценария.

## Java API

[frontend-api.md](../../docs/frontend-api.md) содержит все обновлённые сущности,
DTO, запросы, ответы, права, места вызова и источники полей в одном документе.
Источник ответа — общие данные через Java; UI-типы могут иметь удобную экрану форму.
Python-симулятор вызывает те же PWA-ручки, включая оба варианта отказа;
отдельные пути статусов/задержек/отказов для симулятора не создаём.

HTTP-адаптер обращается только к Java, проверяет внешний JSON и преобразует DTO
в UI-модели. Общие счётчики, карта и детали не зависят от текущей страницы списка.
ID, версии и полные временные значения сохраняются для команд; форматирование
применяется при показе. Автор и роль определяются настоящей сессией Java.

HTTP-адаптер и сессия пока не реализованы. IndexedDB/outbox добавляются отдельным
этапом PWA, а не через сохранение полного Zustand-store.

## Что потребуется при подключении Java

`WorkdayApi` пока сохраняет демосигнатуры: мутации возвращают полный snapshot,
`reset()` синхронный. Java возвращает DTO заявки или подтверждение долгой операции.
Поэтому следующий шаг — HTTP-адаптер с проверкой JSON и преобразованием моделей,
ожидание `operation_id`, затем отдельное обновление нужных сводки/списков/деталей.
Не собирать снимок обходом всех страниц сервера. Сессию, версии и новые возможности
из контракта подключать явно; одних URL недостаточно.

Для текущего демо в DEV доступны `VITE_DEMO_LATENCY_MS` и `VITE_DEMO_FAIL_ONCE`:
задержка и первая ошибка чтения/изменения. Одинаковые параллельные чтения используют
один ожидающий запрос, в том числе при повторе эффекта React StrictMode;
результаты потребителям передаются отдельными копиями. Это не постоянный кеш.
После ошибки/успеха запрос удаляется, сброс дня меняет поколение и счётчики попыток.
Пример запуска и проверки — в [README](../../README.md).
