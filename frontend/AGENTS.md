# RouteRoad: инструкции для frontend

## Контекст и источники

- Общаться по-русски; различать реализованное, демо и предложения.
- Сейчас это React/TypeScript UI на синтетических данных с асинхронным demo API.
  Java HTTP API, настоящая авторизация, оптимизация, PWA, IndexedDB и синхронизация
  ещё не реализованы. Планирование контракта не означает их реализацию.
- Перед предметными изменениями читать [vision](docs/vision.md),
  [решения](docs/decisions.md) и [архитектуру](docs/frontend-architecture.md).
  `vision.md` не изменять без прямого указания пользователя.
- [frontend-api.md](docs/frontend-api.md) — единый результат задачи для Java:
  сначала все обновлённые сущности и DTO, затем ручки. Определения полей и расширения
  схемы не разносить по другим файлам. [entity.md](docs/entity.md) — исходная
  справочная основа Java/Python; UI-модели не обязаны копировать таблицы.
- Источник данных PWA — общая БД через Java. Python-симулятор вызывает те же
  Java-ручки и проходит те же проверки, что PWA; Python-расчётчик остаётся внутренним.
  Поддерживаются отказ от одной заявки и отказ от всех оставшихся на день.

## Структура и границы

- Использовать выбранную layer/type-based структуру: `pages`, `components`,
  `stores`, `hooks`, `api`, `types`, `utils`, `routes`, `config`, `styles`.
  Alias `@/` указывает на `src/`.
- Все файлы и компоненты в `pages` заканчиваются на `Page`. Страницы компонуют
  экраны; общий UI получает props. Контейнеры могут читать stores.
- Zustand-stores дня, демосессии и UI разделены. Изменения проходят через
  store action → `api/workdayApi.ts` → адаптер → snapshot → UI.
  Списки читаются через hooks → API; query-типы находятся в `types`.
- `api/workdayApi.ts` выбирает адаптер. Компоненты, страницы и stores не импортируют
  `api/mock` напрямую; API не импортирует stores, React или страницы.
  `utils` не вызывают API, `types` не содержат runtime-логики. Не вводить циклы.
- Интерфейс источника — `types/workdayApi.ts`. Детали заявки загружаются по ID
  через `getVisitDetails`/`useVisitDetails`, независимо от текущей страницы списка.
  Визуальные ui/map, DaySummary и ReassignDrawer получают данные через props;
  запросы и store остаются в контейнерах. Эти границы проверяет ESLint.
- Бизнес-данные, назначения и геометрия находятся в источнике данных, не в JSX
  или store. Подписи кнопок и пустых состояний допустимы в компонентах.
  Atomic Design — принцип композиции, обязательных `atoms/molecules/organisms` нет.
- Браузерные бизнес-операции обращаются только к Java, не к Python или БД.
  Внешние картографические тайлы — отдельный источник подложки.

## Данные и демосценарий

- День начинается пустым. Вход ничего не загружает. `loadRequests()` загружает
  неназначенные заявки, представителей и офис; `buildRoutes()` отдельно создаёт
  предопределённые назначения и прямые линии. Расчёта маршрутов в браузере нет.
- Store хранит снимок, loading/error, выбор и pending; не дублирует бизнес-правила.
  Сброс инвалидирует ожидающие операции; двойное нажатие не запускает конкурирующие
  изменения. Старые ответы query/revision игнорируются. Ошибка не равна пустому успеху.
- День живёт в памяти и исчезает при перезагрузке. Демороль и имя профиля находятся
  в `sessionStorage`; смена роли сохраняет день в памяти. Это не серверная сессия.
- Поиск, фильтры и пагинация выполняются в адаптере через query. По умолчанию
  `pageSize=10`, селектора размера в UI нет. Лента представителей догружается по 10;
  ошибка следующей порции сохраняет уже загруженные карточки.
- Для локальных ошибок/ожидания использовать DEV-параметры `VITE_DEMO_LATENCY_MS`
  и `VITE_DEMO_FAIL_ONCE` из `.env.example`; production их игнорирует.
  Одинаковые ожидающие чтения объединяются без постоянного кеша. Демо не проверяет
  HTTP/offline; реальный адаптер потребует DTO, async operations и сессии по контракту.
- При интеграции сохранять ID/версии и исходное время из DTO; форматировать для
  отображения в UI. Права, допустимые действия и активация плана принадлежат Java.
  Дополнительные DTO экрана не требуют копировать в браузер серверную схему БД.
- Deadline и модельное время приходят из адаптера. Таймер UI только отображает
  остаток; истечение срока не запускает клиентское перераспределение.
  IndexedDB/outbox и офлайн-PWA остаются планом, не свойством Zustand persist.

## UI, карта и код

- Сохранять согласованное поведение из архитектуры: сворачивание desktop-sidebar
  на самой панели, мобильный бургер, индикаторы открытых алертов, один аватар
  в общей верхней панели, использование ширины планшета.
- `WorkdayMap` получает данные и callbacks через props, не читает бизнес-stores
  и не рассчитывает маршруты. GeoJSON — `[longitude, latitude]`, Leaflet —
  `[latitude, longitude]`. Прямые демолинии не выдавать за дорожную маршрутизацию.
- Открытые алерты отмечаются красными кругами; popup → «Подробнее» открывает заявку.
  Панели карты управляются через ПКМ, удержание 650 ms или Shift+F10; контролы
  и маркеры не перехватывать. OSM-атрибуция видима; без массовой загрузки/офлайн-кеша.
- Авторский CSS один: `src/styles/global.css`; Tailwind в TSX, токены `@theme`.
  Библиотечный `leaflet.css` подключён отдельно. Без динамических `bg-${value}`.
- Иконки UI — именованные SVG-компоненты `lucide-react` через `Icon`;
  цвет наследуется из текста. `public/assets/icons/route.svg` оставлен для favicon.
- Строгий TypeScript, без `any` и подавлений вместо типов. Семантические кнопки
  и ссылки, подписи полей, видимый focus, клавиатура, Escape и возврат фокуса в диалогах.
- Code Inspector включён перед React только для Vite serve без preview:
  Ctrl+Alt+клик, личный `CODE_EDITOR` в `.env.local`. В production нет runtime,
  endpoint и `data-insp`; при smoke перехватывать запрос открытия, не запускать IDE.
- Vite обслуживает dev/HMR; Nginx раздаёт `dist`. До интеграции `/api` возвращает
  JSON 503. Immutable-кеш допустим только для ресурсов с хешем.

## Команды и проверки

Node 24.x, npm, один `package-lock.json`. При блокировке `npm.ps1` использовать
`npm.cmd`, не менять ExecutionPolicy. Запуск — в [README](README.md).

| Команда                                   | Назначение                                                           |
| ----------------------------------------- | -------------------------------------------------------------------- |
| `npm ci` / `npm run dev`                  | Зависимости / Vite на 5173                                           |
| `npm run typecheck` / `npm run lint`      | Типы / ESLint и границы импортов                                     |
| `npm run format:check` / `npm run format` | Проверка / применение Prettier                                       |
| `npm run build` / `npm run preview`       | Проверка типов и сборка / просмотр `dist`                            |
| `docker compose up --build -d`            | Из корня RouteRoad: Nginx на 8080; `docker compose down` — остановка |

Выбирать проверки по изменению: для кода typecheck/lint/format/build и значимые
браузерные сценарии; для документации достаточно форматирования и сверки ссылок.
E2E-набор и Playwright пока удалены по просьбе пользователя; `e2e/` оставлена пустой.
Браузерные проверки выполнять вручную по изменённому сценарию. Живые тайлы
проверять обычной загрузкой viewport без prefetch.
Поддерживать затронутые документы по реальному коду; в отчёте указывать фактически
выполненные проверки и ограничения.
